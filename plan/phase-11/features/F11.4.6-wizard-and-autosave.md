# F11.4.6 — Wizard UX + Autosave + Preview Button

## Goal
Make the product editor feel linear rather than tab-sprawling, keep work safe against abandonment, and surface a preview action everywhere the admin sees a product row.

## Shared Wizard — `src/app/admin/products/[id]/_components/ProductWizard.tsx`

A new client component that the create form and the edit form both consume. Five steps (URL-persisted via `?step=`):

| # | Step | Fields | Validation |
|---|---|---|---|
| 1 | Identity | asin, title (en), slug (auto), category, brand | slug format |
| 2 | Locales | title/slug/description/meta_title/meta_description × {en, bn-BD, sv} | Title required in at least en |
| 3 | Pricing & Features | price, original_price, currency, discount %, availability, features[] | price > 0 |
| 4 | Media | images (with Browse Media → MediaPickerDialog from F13.4), wizard blocks, comparison blocks | first image required |
| 5 | SEO & Publish | meta fields, product_status, scheduled publish_at, Save Draft / Submit for Review | status ∈ enum |

Wizard-level state lives in a single `<ProductFormProvider>` context backed by `useReducer`. **Local state is the source of truth**; the page never trusts the server's last response as truth.

### Route Mounting
- `src/app/admin/products/new/page.tsx` → mounts `<ProductWizard mode="create">`.
- `src/app/admin/products/[id]/page.tsx` → mounts `<ProductWizard mode="edit" initialProduct={...} initialUpdatedAt={...}>`.

The 757-line `ProductEditForm.tsx` is decomposed: the inline tab machinery moves into the wizard, and the autosave/preview/SEO/grammar features stay as composable pieces the wizard steps consume.

### Persistence
`?step=N` in URL; form values in `sessionStorage` keyed by product id (create) or just by url (edit). Refreshing on step 3 with content half-filled returns to step 3 with content intact.

### Feature Flag
`NEXT_PUBLIC_PRODUCT_EDITOR_V2=false` (default for first release) keeps the existing tab-based forms in place; the wizard mounts only when the flag is on. Both code paths must compile and pass tests in every release.

## Autosave — `src/app/admin/products/[id]/_components/useAutosave.ts`

Trigger rules:

| Rule | Reason |
|---|---|
| **Idle 10 s** since last keystroke | Avoid mid-word saves; matches "step away and it persists" UX. |
| Hard cap 1 save / 10 s | Burst protection — continuous typing for 30 s fires ≤ 3 PATCHes. |
| Disabled during destructive actions | Add Image / Add Wizard / Delete FAQ all run their own optimistic update that suppresses autosave until settled. |

Conflict detection:
- On mount, capture `initialUpdatedAt` from the server.
- Every PATCH carries `_autosave: true`.
- Server replies include the canonical `updated_at`. If the response `updated_at` differs from `expectedUpdatedAt`, the route returns a `409` with body `{ error: 'conflict', serverUpdatedAt, serverProduct }`.
- Client shows `<ConflictBanner>` with options **Reload** (discard local changes and apply server's) or **Keep mine** (re-PATCH my state).

## Preview Button

Reused across two surfaces (see F11.4.2):

| Surface | Component | Notes |
|---|---|---|
| `ProductsTable.tsx` | Add `<PreviewButton>` cell before the existing Actions column. Icon `Eye`. | Disabled if minting fails; shows a tooltip with the error. |
| `ProductEditForm` (top header) | Existing single button moves to the right of "Save Draft" / "Submit for Review". | Disabled when form is `dirty && !lastSaveSucceeded`. |

Both go through the same `/admin/api/products/[id]/preview-token` mint. The component is a thin client wrapper:

```tsx
<PreviewButton productId={p.id} locale="en" productStatus={p.product_status} />
```

## Acceptance
- Wizard steps 1–5 advance / retreat freely, the URL records the active step, refresh preserves both step and form content.
- Autosave fires only on idle ≥ 10 s, never mid-word.
- Two-window conflict (open same product in tab A and tab B; save A; type and let autosave fire in B) shows the conflict banner in B.
- Preview button works on every product row in the table, regardless of `product_status`.
- Phase 11.4 ships behind `NEXT_PUBLIC_PRODUCT_EDITOR_V2`; toggling the flag down restores the legacy tab UI without rebuild.

## Rollback
- Feature flag flips the entry point.
- Autosave hook is a no-op when `FEATURE_AUTOSAVE=false`.
- PreviewButton returns null when `FEATURE_PREVIEW_BUTTON=false`.
