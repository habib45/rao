# F11.4.3 — Grammar & Spell Check (Server-Proxied)

## Goal
Surface inline grammar and spelling suggestions inside the rich text editor for the active description tab.

## Why not `@grammarly/editor-sdk`
Browser-only SDK that:
- Posts editor content to Grammarly's servers (privacy concern for product copy).
- Requires `GRAMMARLY_CLIENT_ID` + end-user SSO.
- Has been sunset for direct CKEditor 5 integration.

## Primary Path — LanguageTool
Add `LANGUAGETOOL_API_URL` to env (public `https://api.languagetool.org/v2/check` works for low volume; a self-hosted instance is recommended for production).

### Route — `POST /admin/api/ai/grammar`
Request: `{ text: string; locale: 'en'|'bn-BD'|'sv' }`.

Response: `{ matches: Array<{ start: number; end: number; message: string; shortMessage?: string; replacement?: string; rule: { id: string; category: string } }> }`.

Implementation:
1. Auth: `requireAdmin()`.
2. Zod: `text: z.string().min(1).max(20_000)`, `locale: z.enum(['en','bn-BD','sv'])`.
3. Rate-limit bucket: `ai-grammar` (capacity 20, refill 1 per 3 s) — separate from `ai-generate-description`.
4. LanguageTool call: `POST ${LANGUAGETOOL_API_URL}/check` with form-encoded `text`, `language: <lang code>`. Map `bn-BD` → `bn-BD`, `sv` → `sv`.
5. Map LT matches → our contract. Filter out matches whose `replacement` would corrupt HTML (see sanitize below).
6. Fallback: if LT returned 0 matches and the locale is `bn-BD` (LT coverage is thinner), call the existing `generate-description` route with `mode: 'grammar'` and merge results.

### Sanitize
Reject any `replacement` that changes length-when-emitted ≠ `end - start` by more than 2 chars OR that contains unescaped `<` / `>` / `&` for the **en** locale. The ar/te interface is tolerant of HTML in editor text; LT replacements should be plain-text suggestions.

## Toolbar UI — `src/app/admin/_components/ui/RichTextEditor.tsx`
Add a `"Check grammar"` button (icon: `Sparkles`) that:

1. Calls `/admin/api/ai/grammar` with `editor.getData()` and the active locale.
2. On success, applies decorations via `editor.model.change(writer => writer.addMarker(...))` — yellow underline per match's range.
3. On click of a marker, shows a `Popover` with the message and an "Apply" button that swaps the range with `replacement`.
4. On locale change, clears all markers.

## Fallback Path (LLM)
Behind a server-side flag `FEATURE_LLM_GRAMMAR` (default `false`), the LLM path is available when LT matches are empty for `bn-BD`. Adds the `mode: 'grammar'` parameter to `src/app/admin/api/ai/generate-description/route.ts` reusing the same provider config as F11.4.4.

## Acceptance
- "Check grammar" toolbar button calls the route, applies decorations, and lets the admin apply each suggestion per click.
- bn-BD / sv support via LanguageTool where coverage exists; falls back to the LLM when LT is silent.
- Editor never loses characters when a marker is rejected; cancellation works cleanly.
- A second invocation within 3 s is rate-limited (HTTP 429) with a clear toast.

## Rollback
Disable the toolbar button via `FEATURE_GRAMMAR=false`; the route is left dormant (no client callers).
