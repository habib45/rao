# F11.4.2 — Public Preview with Signed Token

## Goal
Let an admin open the public product page in a new tab — for drafts, rejected, scheduled, or published products — without publishing first, and without auth on the public route.

## UX
Two surfaces share one `PreviewButton` component:

| Surface | Where | Action |
|---|---|---|
| Product list | `src/app/admin/products/_components/ProductsTable.tsx`, new column at the end (icon: `Eye`) | Click → fetch token → `window.open(url, '_blank', 'noopener')` |
| Edit page header | `src/app/admin/products/[id]/_components/ProductEditForm.tsx`, top-right | Same flow; disabled while form is `dirty && !saved` |

The button shows a small `Loading…` spinner while minting.

## Token Contract

```ts
// POST /admin/api/products/[id]/preview-token
{
  locale: 'en' | 'bn-BD' | 'sv';  // default 'en'
}
// 200:
{
  url: string;          // e.g. `/en/products/<slug>?preview=<base64url(hmac(payload))>&pid=<id>`
  expiresAt: string;    // ISO; 15 min from now
}
```

The HMAC payload (signed with `MYSQL_PREVIEW_SECRET`):

```ts
{ id: string; userId: string; locale: 'en'|'bn-BD'|'sv'; exp: number /* Unix seconds */ }
```

Header `<base64url(payload)>.<base64url(hmac)>`. Constant-time compare on verify.

## Public Route Branch — `src/app/[locale]/products/[slug]/page.tsx`

| Phase | Change |
|---|---|
| `generateMetadata` | Reject preview mode via `notFound()` so OG cards aren't accidentally indexed. |
| Page body | Read `preview` search param. If HMAC verify succeeds AND `Date.now()/1000 < exp`, render the product exactly as the public storefront would **plus** a sticky `<PreviewBanner locale={locale} />` at the top. |
| Response headers | Set `Cache-Control: private, no-store` and `X-Robots-Tag: noindex`. Add the route segment to `next.config.js` `experimental.noStore` so `revalidate = 3600` does not cache it. |
| Token failures | Expired / tampered → 404 page with copy "Preview link expired — return to the admin editor and try again." |

## Middleware Bypass — `src/middleware.ts`
The current `next-intl` middleware strips the locale prefix when the URL points at a slug that isn't yet a real product. Add an explicit early-return when `request.nextUrl.searchParams.has('preview')`:

```ts
if (searchParams.has('preview')) return NextResponse.next({ request: { headers: requestHeaders } });
```

This lets the preview branch locate the product by UUID for drafts that don't have a slug yet.

## Conflict with Slug-less Drafts
Two scenarios:

| Scenario | Behavior |
|---|---|
| Published row, has slug | URL uses `/<locale>/products/<slug>?preview=…`. |
| Draft, no slug | URL uses `/<locale>/products/<id>?preview=…`. The public page falls back to `getProductById` only if a valid preview token is present; otherwise it 404s normally. |

## Acceptance
- Admins see the actual rendered public page in any status, in any of the 3 locales, with a visible "Preview mode" banner.
- Public store and search engines never see preview content (noindex + no-store + 404 on missing/malformed tokens).
- Tokens expire in 15 minutes; copying a leaked URL after that expiry surfaces the "Preview link expired" page.
- Mid-route preview headers (`Cache-Control: no-store`, `X-Robots-Tag: noindex`) prevent ISR pollution.

## Rollback
Disable the middleware bypass via `FEATURE_PREVIEW_TOKEN=false`. The token route returns 503 and the button shows "Preview disabled in this build".
