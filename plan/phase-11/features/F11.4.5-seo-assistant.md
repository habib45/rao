# F11.4.5 — SEO Assistant Panel

## Goal
Score and rewrite the product's search-engine preview (title, meta_title, meta_description) and surface a per-locale checklist inside the product edit page.

## UX
A new `<SeoAssistant>` panel, embedded in the SEO tab of `ProductEditForm.tsx`. Renders one column per locale (en / bn-BD / sv).

Each column shows:

| Section | Source |
|---|---|
| Numeric score (0–100) | Client-side deterministic scoring (see below). |
| 5-line checklist | Live; re-evaluates on every keystroke via `useDeferredValue`. |
| "Suggest rewrite" button | Calls `/admin/api/ai/seo-suggest`. |
| Search preview card | Google-style SERP: blue title (50–60 chars), green URL, gray meta description (~155 chars), with red marker when over limits. |

## Deterministic Scoring — Client-Side

```ts
function scoreSeo(input: { title: string; metaTitle: string; metaDescription: string; h1: string; }, rules: SeoRules): { score: 0..100; checks: CheckResult[] }
```

Rules:

| Check | Pass | Weight |
|---|---|---|
| meta_title length 50–60 chars | +20 | 20 |
| meta_description length 140–160 chars | +20 | 20 |
| H1 contains primary keyword | +15 | 15 |
| meta_title starts with primary keyword | +15 | 15 |
| meta_description contains primary keyword | +10 | 10 |
| Title unique against existing products | +10 | 10 (skipped client-side; resolved by server) |
| Description has at least one CTA ("Shop", "Buy", "Compare") | +10 | 10 |

`primary keyword` defaults to the first 1–3 word noun chunk of `title`; user can override via a `<select>` populated from existing keywords.

## AI Rewrite Route — `POST /admin/api/ai/seo-suggest`
Request:

```ts
{
  locale: 'en'|'bn-BD'|'sv',
  title: string,
  meta_title: string,
  meta_description: string,
  primary_keyword?: string,
}
```

Response:

```ts
{
  score: 0..100,
  suggestions: Array<{ field: 'meta_title'|'meta_description'|'title'; current: string; suggestion: string; rationale: string; }>,
  meta_title: string,       // best-effort rewrite
  meta_description: string, // best-effort rewrite
}
```

Implementation:

1. Auth: `requireAdmin()`.
2. Zod: string fields with max 200 chars each.
3. Rate-limit bucket: `ai-seo-suggest` — separate from `ai-generate-description`. Capacity 20, refill 1 per 4 s. The SEO panel is a noisy surface; keeping it siloed prevents starvation.
4. Compose prompt with the deterministic score (so the LLM doesn't have to redo cheap work) and ask for:
   - `meta_title` ≤ 60 chars, includes `primary_keyword` at the start.
   - `meta_description` ≤ 160 chars, mentions feature/benefit and ends with a CTA verb.
   - 3 short `suggestions` explaining what was changed and why.
5. Provider priority: `groq` (Llama 3.3 70B) → `gemini-1.5-flash` → `openai-gpt-4o-mini`.
6. Parse via `parseAIJSON` (existing helper in `src/lib/json-parser.ts`).

## Acceptance
- Live score updates on every keystroke without layout shift.
- "Suggest rewrite" populates meta_title/meta_description fields but **never** overwrites the user's typing until the admin clicks "Apply".
- 429 from rate-limit surfaces a friendly "Slow down — try again in a few seconds" toast.
- All three locales carry the same panel strings (`messages/{en,bn-BD,sv}.json`).
