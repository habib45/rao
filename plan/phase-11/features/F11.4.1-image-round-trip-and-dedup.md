# F11.4.1 — Image Round-Trip Fix + Perceptual Dedup

## Goal
Eliminate the "removed image reappears on save" bug and prevent near-duplicate images from being persisted.

## Root Cause
`src/app/admin/api/products/[id]/route.ts` (PATCH handler) currently does:

```ts
if (images !== undefined) {
  await fetch(`${MYSQL_API_URL}/api/products/${id}/images`, { method: "DELETE" });
  for (const img of images) {
    await fetch(`${MYSQL_API_URL}/api/products/${id}/images`, { method: "POST", ... });
  }
}
```

DELETE-then-N-POST is **non-transactional**. A failure on POST #k mid-loop leaves the previous rows deleted and the later rows not re-inserted, so partial state from earlier saves can re-appear if the client retries. The fix is structural, not a guard.

## Three-Part Fix

### Part A — Idempotent Gateway Endpoint
Add `PUT /api/products/:id/images` to the MySQL gateway:

| Field | Value |
|---|---|
| Method | `PUT` |
| Body | `{ images: Array<{ url: string; sort_order: number; phash?: string; color_hist?: number[] }> }` |
| Behavior | Begin tx → truncate `product_images WHERE product_id = :id` → bulk insert → commit. On any failure, rollback. |
| Response | `{ images: Array<{ id, url, sort_order, is_duplicate_of: number \| null, phash }>, updated_at: ISODateString }` |
| Idempotency | Same body sent twice produces the same row set. Re-running cannot resurrect stale rows. |

### Part B — Database Constraints
Migration `supabase/migrations/00010_product_image_dedup.sql`:

```sql
ALTER TABLE product_images
  ADD COLUMN IF NOT EXISTS phash CHAR(16) NULL,
  ADD COLUMN IF NOT EXISTS color_hist JSON NULL,
  ADD COLUMN IF NOT EXISTS is_duplicate_of BIGINT UNSIGNED NULL;

CREATE UNIQUE INDEX IF NOT EXISTS uq_product_image_phash
  ON product_images (product_id, phash)
  WHERE phash IS NOT NULL;

CREATE INDEX IF NOT EXISTS idx_product_image_duplicate
  ON product_images (product_id, is_duplicate_of);
```

The `(product_id, phash)` UNIQUE constraint is the durable safety net: even if a future code path forgets to dedup, the database throws on insert.

### Part C — Client Diff-Based PATCH
In `src/app/admin/products/[id]/_components/ProductEditForm.tsx`:

| State | Behavior |
|---|---|
| `lastSavedImagesHash` | Stable SHA-256 over the sorted image URL list, kept in a `useRef` |
| On user mutation | Recompute, send `PATCH` with body `{ images: <current list> }` only when the hash differs |
| On PATCH success | Replace hash reference with the **server-echoed canonical list**. Local form state becomes the post-save state. |
| On PATCH failure | Show error toast; retain local list; on next attempt reuse the canonical state from the last successful save. |

The PATCH route now calls `PUT /api/products/:id/images` exactly once, with the full intended set (DELETE+POST loop deleted).

## Perceptual Dedup Library — `src/lib/images/dedup.ts`
Library API (pure, no DOM):

```ts
export interface DedupInput { url: string; sort_order?: number; }
export interface DedupOutput { kept: DedupInput[]; dropped: Array<{ url: string; reason: 'phash' | 'color_hist'; duplicate_of: string }>; }

/** Fetch + hash; returns DedupOutput. Caller supplies a fetcher (browser fetch in prod, undici in tests). */
export async function deduplicateImages(input: DedupInput[], opts?: { threshold?: number; fetcher?: typeof fetch }): Promise<DedupOutput>;
```

Algorithm:

| Step | Detail |
|---|---|
| 1. Filter | Drop empty URLs and obvious junk (length < 8, no `/` in path). |
| 2. Fetch bytes | Use `globalThis.fetch`; cap payload at 5 MB; cache by URL for the duration of the call. |
| 3. dHash | 9-byte perceptual hash via dHash (8x8 luminance diff). Implemented in pure TS. |
| 4. Color histogram | 16-bin RGB histogram → cosine similarity matrix. |
| 5. Cluster | Union-find on pairs with Hamming distance ≤ 4 over dHash **or** cosine similarity ≥ 0.97 on histogram. |
| 6. Drop order | Within a cluster, keep the row with the lowest `sort_order` (then earliest URL alphabetically); mark the rest with `duplicate_of` pointing at the kept row. |

Pure-function architecture so the same logic is reused in:

- `src/lib/amazon/transformers.ts` → at Amazon import time (extends the existing exact-URL dedupe).
- `ProductEditForm.tsx` → at manual image-add time (paste URL → preview hash → "Looks duplicate of image #3 — replace?").
- Gateway → at write time (defense in depth; UNIQUE constraint is the final layer).

## Tests
See `tests/TEST_MATRIX.md` rows 1–4. Three pure-function tests plus one round-trip regression.

## Acceptance
- Removing any image and saving leaves the page in the expected state on reload — no resurrection.
- A user manually pasting the same image URL twice triggers the dedup warning before the second row is added.
- A `(product_id, phash)` UNIQUE constraint violation surfaces as a 409 from the gateway, not a 500.
- Re-importing the same ASIN yields an identical image set as the first import.

## Rollback
- The new `PUT /images` endpoint is additive. Toggling `NEXT_PUBLIC_PRODUCT_EDITOR_V2=false` keeps the old DELETE/POST path active.
- The schema columns are nullable; the UNIQUE index is `WHERE phash IS NOT NULL`, so pre-existing rows without `phash` are unaffected.
