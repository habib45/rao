# F1.4 — Internationalization (next-intl)

## Description

Configure next-intl for 3 locales (en, bn-BD, sv) with locale-aware routing, middleware for locale detection, translation message files, and two utility functions: `t()` for TranslationMap lookups and `formatPrice()` for locale-aware currency formatting.

## Business Logic

### Locale Routing
- URL pattern: `/{locale}/...` (e.g., `/en/products/headphones`, `/bn-BD/products/headphones`)
- Default locale: `en`
- Supported locales: `en`, `bn-BD`, `sv`
- Middleware detects locale from: (1) URL prefix, (2) Accept-Language header, (3) falls back to `en`

### Translation Sources
1. **Database fields** (products, categories): JSONB `TranslationMap` — accessed via `t()` helper
2. **UI strings** (buttons, labels, nav): JSON message files — accessed via next-intl's `useTranslations()`

### t() Helper — TranslationMap Lookup
```typescript
// lib/i18n/translate.ts
export function t<T>(map: TranslationMap<T> | undefined | null, locale: LocaleCode): T | string {
  if (!map) return '';
  return map[locale] ?? map['en'] ?? '';
}
```
- Always falls back to `en` if the requested locale is missing.
- Returns empty string if the map is null/undefined or `en` is also missing.
- Generic: works with `TranslationMap<string>` and `TranslationMap<string[]>`.

### formatPrice() — Currency Formatting
```typescript
// lib/i18n/format.ts
export function formatPrice(
  cents: number | null,
  currency: string = 'USD',
  locale: LocaleCode
): string {
  if (cents === null || cents === undefined) return '';
  const localeMap: Record<LocaleCode, string> = {
    'en': 'en-US',
    'bn-BD': 'bn-BD',
    'sv': 'sv-SE',
  };
  return new Intl.NumberFormat(localeMap[locale], {
    style: 'currency',
    currency,
    numberingSystem: 'latn',  // Always use Western Arabic numerals
  }).format(cents / 100);
}
```
- Converts cents to dollars before formatting.
- Uses `numberingSystem: 'latn'` to ensure Western Arabic numerals in all locales (including bn-BD which defaults to Bengali numerals).
- Returns empty string for null/undefined cents.

## API Requirements

None — i18n is frontend-only. Database translations are fetched via Supabase queries.

## UI Behavior

| Element | Behavior |
|---|---|
| URL bar | Shows `/{locale}/path` |
| `<html lang>` | Set to current locale |
| Text direction | Always `ltr` (no RTL locales) |
| Locale switcher | Dropdown with en/bn-BD/sv; preserves current path; changes URL prefix |
| Missing translation key | Falls back to `en` value via next-intl's fallback config |
| Price display | Formatted per locale with `numberingSystem: 'latn'` |

## Edge Cases

| Case | Expected Behavior |
|---|---|
| URL with no locale prefix (e.g., `/products`) | Middleware redirects to `/en/products` |
| URL with unsupported locale (e.g., `/fr/products`) | Middleware redirects to `/en/products` |
| TranslationMap with only `en` key | `t(map, 'bn-BD')` returns the `en` value |
| TranslationMap is null | `t(null, 'en')` returns `''` |
| TranslationMap is empty `{}` | `t({}, 'en')` returns `''` |
| formatPrice with null cents | Returns `''` |
| formatPrice with 0 cents | Returns `$0.00` (or locale equivalent) |
| formatPrice with negative cents | Formats correctly with minus sign (edge case for refunds) |
| bn-BD locale without numberingSystem override | Would show Bengali digits; our config forces 'latn' |
| Very large price (e.g., 99999999 cents) | Intl.NumberFormat handles gracefully: `$999,999.99` |
| Currency other than USD | formatPrice respects the currency parameter |
| Switching locale preserves scroll position | next-intl router handles; no custom logic needed |
| SEO: hreflang tags | Handled in Phase 6; i18n config provides locale list |

## Acceptance Criteria

- [ ] Middleware redirects `/` to `/en`
- [ ] Middleware redirects unknown locales to `/en`
- [ ] `/en`, `/bn-BD`, `/sv` all resolve to the locale layout
- [ ] `t()` returns en fallback when locale key is missing
- [ ] `t()` returns empty string for null/undefined input
- [ ] `formatPrice(1999, 'USD', 'en')` returns `$19.99`
- [ ] `formatPrice(1999, 'USD', 'bn-BD')` returns Bengali-formatted price with Western digits
- [ ] `formatPrice(1999, 'SEK', 'sv')` returns Swedish krona formatted price
- [ ] `formatPrice(null, 'USD', 'en')` returns `''`
- [ ] All 3 message files (en.json, bn-BD.json, sv.json) exist and have matching keys
- [ ] `useTranslations('product')` works in client components
- [ ] `<html lang={locale}>` is set correctly per route
