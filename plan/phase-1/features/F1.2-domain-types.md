# F1.2 — TypeScript Domain Types

## Description

Define all core domain types used across the application. These types represent the data model for products, categories, cart items, images, and locale configuration. They serve as the single source of truth for all TypeScript code.

## Business Logic

- All translated database fields use a `TranslationMap` pattern: a partial record keyed by `LocaleCode` with `en` as the required fallback.
- Prices are stored as integers (cents) to avoid floating-point precision issues.
- Product availability is a closed union type, not a free string.
- The `Product` interface includes a nested `product_images` array (matching the Supabase join pattern).
- `CartItem` wraps a `Product` with a quantity constraint (1–99).

## Types to Define

### LocaleCode
```typescript
type LocaleCode = 'en' | 'bn-BD' | 'sv';
```

### TranslationMap<T>
```typescript
type TranslationMap<T = string> = Partial<Record<LocaleCode, T>>;
```
- Allows any subset of locales.
- `en` is not required at the type level (the database ensures it), but the `t()` helper always falls back to `en`.

### Product
```typescript
interface Product {
  id: string;                           // UUID
  asin: string;                         // Amazon Standard Identification Number
  category_id: string | null;
  name: TranslationMap;
  slug: TranslationMap;
  description: TranslationMap;
  features: string[];                   // bullet points from Amazon
  meta_title: TranslationMap;
  meta_description: TranslationMap;
  price_cents: number | null;           // current price in cents
  original_price_cents: number | null;  // list/was price in cents
  currency: string;                     // ISO 4217 (e.g. "USD")
  discount_pct: number;                 // computed: 0–100
  rating: number | null;                // 0.0–5.0
  review_count: number;
  affiliate_url: string;
  brand: string | null;
  availability: ProductAvailability;
  is_featured: boolean;
  is_active: boolean;
  product_images: ProductImage[];
  created_at: string;                   // ISO 8601
  updated_at: string;                   // ISO 8601
}
```

## API Requirements

None — these are TypeScript-only types with no runtime cost.

## UI Behavior

None — types are consumed by components in later phases.

## Edge Cases

| Case | Expected Behavior |
|---|---|
| TranslationMap with missing locale | `t()` helper returns `en` value; type allows partial |
| Product with null price_cents | UI shows "Price unavailable"; discount_pct should be 0 |
| Product with null rating | UI hides rating stars; no aggregateRating in JSON-LD |
| ProductImage with null width/height | Omit width/height attributes; let browser determine |
| Empty features array | Product detail page shows no bullet points section |
| CartItem quantity = 0 | Should be impossible (removeItem instead); type doesn't prevent it but runtime does |
| Category with null parent_id | Top-level category; no breadcrumb parent |

## Acceptance Criteria

- [ ] All types compile without errors under strict mode
- [ ] Types are exported from a single `types/domain.ts` file
- [ ] `LocaleCode` is a union of exactly 3 values
- [ ] `TranslationMap` accepts a generic type parameter
- [ ] `ProductAvailability` is a closed union (no arbitrary strings)
- [ ] `Product.price_cents` is `number | null` (not just `number`)
- [ ] All interfaces use `string` for UUID fields (not a branded type — simplicity first)
- [ ] Type tests verify assignability and constraint enforcement
