# F1.1 — Project Initialization & Configuration

## Description

Initialize a Next.js 15 App Router project with TypeScript strict mode, Tailwind CSS, and ESLint. Install all Phase 1 dependencies. Configure the project structure, environment variables, and build tooling.

## Business Logic

- The project must build and run without errors from the first commit.
- All configuration must support the full stack: Next.js 15 App Router, Supabase, next-intl, Tailwind CSS.
- Environment variables must be documented but never committed with real values.

## Configuration Files

### next.config.ts
- Enable next-intl plugin
- Configure image remotePatterns for Amazon CDN (`images-na.ssl-images-amazon.com`, `m.media-amazon.com`)
- No experimental flags unless required

### tsconfig.json
- strict: true
- paths: `@/*` → `./src/*`
- target: ES2022, module: ESNext

### tailwind.config.ts
- Content paths: `./src/**/*.{ts,tsx}`
- Extend theme with amber-500 brand color if needed

### .env.example
```
NEXT_PUBLIC_SUPABASE_URL=
NEXT_PUBLIC_SUPABASE_ANON_KEY=
NEXT_PUBLIC_SITE_URL=http://localhost:3000
```

### vitest.config.ts
- Environment: jsdom
- Setup file for @testing-library/jest-dom
- Path aliases matching tsconfig

## API Requirements

None — this feature is configuration only.

## UI Behavior

None — no visual output. `npm run dev` must start the dev server successfully.

## Edge Cases

| Case | Expected Behavior |
|---|---|
| Missing .env file | App starts but Supabase client throws at runtime (documented in .env.example) |
| Node.js < 18 | next.config should not break; engines field in package.json enforces >= 18 |
| Tailwind CSS not processing | Verify postcss.config has tailwindcss plugin; verify content paths |
| TypeScript strict mode catches existing code | All code must pass strict checks from day 1 |

## Acceptance Criteria

- [ ] `npm run dev` starts without errors on port 3000
- [ ] `npx tsc --noEmit` passes with zero errors
- [ ] `npm run lint` passes with zero warnings
- [ ] `npm run test` runs vitest successfully (even if no tests yet)
- [ ] `.env.example` documents all required environment variables
- [ ] No real secrets committed to git
- [ ] `@/*` path alias resolves correctly in TypeScript
