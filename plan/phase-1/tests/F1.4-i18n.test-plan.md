## A. translate.ts — t() Helper

### Unit Tests

#### TC-1.4.1: t() returns exact locale value
```
Test: t({ en: 'Hello', 'bn-BD': 'হ্যালো', sv: 'Hej' }, 'bn-BD')
Assert: 'হ্যালো'
```

#### TC-1.4.2: t() returns en value for each locale when present
```
Test: t({ en: 'Hello', 'bn-BD': 'হ্যালো', sv: 'Hej' }, 'en')
Assert: 'Hello'
Test: t({ en: 'Hello', 'bn-BD': 'হ্যালো', sv: 'Hej' }, 'sv')
Assert: 'Hej'
```

#### TC-1.4.3: t() falls back to en when locale is missing
```
Test: t({ en: 'Hello' }, 'bn-BD')
Assert: 'Hello'
Test: t({ en: 'Hello' }, 'sv')
Assert: 'Hello'
```

#### TC-1.4.4: t() returns empty string for null map
```
Test: t(null, 'en')
Assert: ''
```

#### TC-1.4.5: t() returns empty string for undefined map
```
Test: t(undefined, 'en')
Assert: ''
```

#### TC-1.4.6: t() returns empty string for empty map
```
Test: t({}, 'en')
Assert: ''
```

#### TC-1.4.7: t() works with TranslationMap<string[]>
```
Test: t({ en: ['Feature A', 'Feature B'], sv: ['Funktion A'] }, 'sv')
Assert: ['Funktion A']
Test: t({ en: ['Feature A', 'Feature B'] }, 'bn-BD')
Assert: ['Feature A', 'Feature B']  (fallback to en)
```

### Edge Case Tests

#### TC-1.4.8: t() with en value as empty string
```
Test: t({ en: '' }, 'en')
Assert: ''  (empty string is a valid value, not a missing key)
```

#### TC-1.4.9: t() with locale value as empty string
```
Test: t({ en: 'Hello', 'bn-BD': '' }, 'bn-BD')
Assert: ''  (explicit empty string for locale takes priority over en fallback)
Note: This is intentional — if a locale explicitly has '', it means "no text here"
```

#### TC-1.4.10: t() preserves Unicode characters
```
Test: t({ en: 'Price', 'bn-BD': 'মূল্য' }, 'bn-BD')
Assert: 'মূল্য'  (Bengali script preserved exactly)
Test: t({ en: 'Price', sv: 'Pris — 100 kr' }, 'sv')
Assert: 'Pris — 100 kr'  (em dash and special chars preserved)
```

Assert: '$19.99'
```

#### TC-1.4.12: formatPrice zero cents

Assert: '$0.00'
```

#### TC-1.4.13: formatPrice large amount
```
Test: formatPrice(99999999, 'USD', 'en')
Assert: '$999,999.99'
```

#### TC-1.4.14: formatPrice null returns empty string
```
Test: formatPrice(null, 'USD', 'en')
Assert: ''
```

#### TC-1.4.15: formatPrice Swedish krona
```
Test: formatPrice(19900, 'SEK', 'sv')
Assert: Contains '199' and 'kr' (exact format depends on Intl locale data)
```

#### TC-1.4.16: formatPrice Bengali locale uses Western digits
```
Test: formatPrice(1999, 'USD', 'bn-BD')
Assert: Output contains '19' and '99' (Western Arabic numerals)
Assert: Output does NOT contain Bengali digits (০-৯)
Note: This verifies numberingSystem: 'latn' override
```

#### TC-1.4.17: formatPrice with BDT currency
```
Test: formatPrice(500000, 'BDT', 'bn-BD')
Assert: Contains '5,000' (or locale-appropriate grouping) and BDT symbol
Assert: Uses Western digits (not Bengali)
```

#### TC-1.4.18: formatPrice single cent
```
Test: formatPrice(1, 'USD', 'en')
Assert: '$0.01'
```

### Edge Case Tests

#### TC-1.4.19: formatPrice negative amount
```
Test: formatPrice(-1999, 'USD', 'en')
Assert: '-$19.99' or '($19.99)' (locale-dependent negative format)
Note: Negative prices shouldn't normally occur but must not crash
```

#### TC-1.4.20: formatPrice with unknown currency code

```

#### TC-1.4.21: formatPrice with undefined cents
```
Test: formatPrice(undefined as any, 'USD', 'en')
Assert: '' (same as null handling)
```

### Integration Tests

#### TC-1.4.22: Root URL redirects to /en

Assert: Response is redirect (302/307) to '/en'
```
