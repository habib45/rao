### Unit Tests

#### TC-1.3.1: createBrowserClient returns a Supabase client
```
Test: Call createBrowserClient() with env vars set
Assert: Returns an object with .from(), .auth, .storage properties
Assert: Return type is SupabaseClient
Type: Unit
Coverage: Browser client factory
```

#### TC-1.3.2: createBrowserClient reads correct env vars
```
Test: Set NEXT_PUBLIC_SUPABASE_URL='https://test.supabase.co'
      Set NEXT_PUBLIC_SUPABASE_ANON_KEY='test-anon-key'
      Call createBrowserClient()
Assert: Client is configured with the test URL and key
Type: Unit (mocked env)
Coverage: Environment variable binding
```

#### TC-1.3.3: createServerClient returns a Supabase client
```
Test: Mock next/headers cookies() to return a cookie store
      Call createServerClient()
Assert: Returns an object with .from(), .auth, .storage properties
Type: Unit (mocked cookies)
Coverage: Server client factory
```

#### TC-1.3.4: Server client integrates with cookies
```
Test: Mock cookies().getAll() to return [{ name: 'sb-token', value: 'abc' }]
      Call createServerClient()
Assert: getAll callback is wired to cookieStore.getAll

#### TC-1.3.5: Server client handles cookie write errors
```

### Failure Scenarios

#### TC-1.3.12: Invalid Supabase URL format
```
Test: Set NEXT_PUBLIC_SUPABASE_URL='not-a-url'
      Call createBrowserClient()
Assert: Client created (SDK may not validate URL eagerly)
      Call .from('products').select('*')
Assert: Returns error (network failure or invalid URL)
Type: Failure
Coverage: Bad configuration resilience
```

#### TC-1.3.13: Server client import in client component (conceptual)
```
Test: Document that importing server.ts in a 'use client' file
      will fail because cookies() is server-only
Assert: This is enforced by Next.js/React, not our code
Note: This is a conceptual test — verified by code review, not automated
Type: Failure (documented)
Coverage: Import boundary enforcement
```
