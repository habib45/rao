# F18.1 — Blog Pagination Options & Filtering

## Goal
Replace the fixed 12-post page size with user-selectable per-page options and add server-side category + keyword filters.

## Query Param Contract

| Param | Values | Default |
|---|---|---|
| `page` | integer ≥ 1 | 1 |
| `perPage` | 20 \| 50 \| 100 | 20 |
| `category` | blog_categories.slug (en) | — |
| `q` | text search string | — |

## Changes

### `src/lib/queries/blog.ts`
- `getPublishedBlogPosts(limit, offset, categoryId?, search?)` — add `.eq("blog_category_id", categoryId)` and `.textSearch("search_vector", search)` branches
- `getPublishedBlogPostsCount(categoryId?, search?)` — same filters for accurate total

### `src/app/[locale]/blog/page.tsx`
- Read `perPage`, `category`, `q` from `searchParams`; validate/clamp perPage to [20, 50, 100]
- Resolve `categoryId` by finding matching slug in fetched categories
- Pass `categoryId` and `search` to both query functions
- Render `<PerPageSelector>` (client, replaces URL param), `<CategoryFilter>` (link-based), `<SearchBar>` (client, debounced 300 ms, replaces URL param)
- Active-filter chips: show when category or q is set, with ✕ link to clear

## Components (all client, minimal — inline in page or small files in blog dir)

- `PerPageSelector` — `<select>` with options 20/50/100; on change `router.push` with updated perPage + reset page=1
- `BlogSearchBar` — controlled input; debounce 300 ms; `router.push` with updated q + reset page=1
- Category links in sidebar already navigate to `?category=<slug>` (URL param approach, no client state needed)

## Acceptance Criteria
- Changing per-page updates URL and fetches correct count
- Category filter shows only posts in that category; "All" link clears filter
- Search filter uses Postgres tsvector; partial word matches are fine (prefix `foo:*` if needed)
- Page resets to 1 when perPage or filter changes
- Pagination shows correct total pages for current filter state
