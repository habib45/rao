# F15.2 — Public-side Settings Query Helper

## Goal
Expose `getSiteSettings()` — a cached server-side function that reads `show_price` from `admin_settings` — so all public server components can consume it without N+1 DB calls.

## Files
| Action | Path |
|---|---|
| Create | `src/lib/queries/settings.ts` |
| Modify | `src/app/admin/api/settings/route.ts` (add cache invalidation on PATCH) |

## getSiteSettings()
```ts
import { unstable_cache } from "next/cache";
import { createAdminClient } from "@/lib/supabase/admin";

export const getSiteSettings = unstable_cache(
  async () => {
    const supabase = createAdminClient();
    const { data } = await supabase
      .from("admin_settings")
      .select("key, value")
      .eq("key", "features")
      .single();
    const features = (data?.value as Record<string, unknown>) ?? {};
    return {
      showPrice: (features.show_price as boolean) ?? true,
    };
  },
  ["site-settings"],
  { revalidate: 60, tags: ["site-settings"] }
);
```

## Cache Invalidation
After a successful PATCH in `/admin/api/settings/route.ts`, call:
```ts
import { revalidateTag } from "next/cache";
revalidateTag("site-settings");
```
This ensures the public site reflects the new setting within one request cycle.
