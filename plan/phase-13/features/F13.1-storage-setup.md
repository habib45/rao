# F13.1 — Storage Setup & RLS

## Bucket Configuration
- Name: `media`.
- Public: `true` (reads are unauthenticated; writes require service role).
- Default MIME types: images only (enforced client-side and on the upload route).

## Create via SQL (idempotent)
```sql
INSERT INTO storage.buckets (id, name, public)
VALUES ('media', 'media', true)
ON CONFLICT (id) DO UPDATE SET public = true;
```

## RLS on `storage.objects`
Supabase enables RLS on `storage.objects` by default. We add:

```sql
-- Public read
CREATE POLICY "Public read media"
  ON storage.objects FOR SELECT
  TO anon, authenticated
  USING (bucket_id = 'media');

-- Admin writes via service role bypass RLS; no INSERT/DELETE policy required.
-- Authenticated non-admin users cannot write (no policy means deny).
```

If the above policies already exist (from a previous environment setup), the migration should be wrapped in `IF NOT EXISTS` guards via `DO $$`.

## Folder Semantics
Supabase Storage is flat — "folders" are a path convention. We emulate folders by:
- On "create folder", uploading a zero-byte object at `<folder>/.keep`.
- Listing with `storage.list(path, { limit, offset, sortBy: { column: 'name', order: 'asc' } })` returns entries whose `id` is `null` for folders and non-null for files; the UI groups folders first.

## Env Vars
No new env vars. Uses the existing `SUPABASE_SERVICE_ROLE_KEY` on the server and the public bucket URL `${NEXT_PUBLIC_SUPABASE_URL}/storage/v1/object/public/media/`.
