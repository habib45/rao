# F12.3 — Admin Review Moderation

## Page: `src/app/admin/reviews/page.tsx`

Server component that requires admin and renders `ReviewModerationTable` inside `AdminShell`.

### UI
- Tabs: Pending · Approved · Rejected.
- Active tab defaults to Pending.
- Table columns: product (thumbnail + name), reviewer name, email, rating (stars), title, body excerpt (first 120 chars), date.
- Row actions: Approve (green), Reject (red) — both open a small dialog with an optional `admin_note` textarea and a confirm button.

### Data Fetching
Server-side fetch via `createAdminClient()` on page load. Pagination is 25 rows per page. URL param `?status=pending|approved|rejected&page=1`.

## API Routes

### `GET /admin/api/reviews`
`src/app/admin/api/reviews/route.ts`

- Guard: `requireAdmin()`.
- Query params: `status` (default `pending`), `page` (default 1), `pageSize` (default 25, max 100).
- Returns `{ reviews: ProductReview[], total: number, page, pageSize }`.
- Joins `products(name)` so the table can show product name in the admin's language (English).

### `PATCH /admin/api/reviews/[id]`
`src/app/admin/api/reviews/[id]/route.ts`

- Guard: `requireAdmin()`.
- Body: `reviewModerateSchema` (`{ status: 'approved'|'rejected', admin_note?: string|null }`).
- Updates and returns the row.

## AdminShell Sidebar
New link `Reviews` with `MessageSquare` icon from lucide.

## Edge Cases
- Moderating a review that's already in the chosen status is a no-op but still returns 200.
- Deleting is out of scope — reject covers it.
- Admin notes can be empty strings; the schema transforms `""` → `null`.
