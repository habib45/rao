# F9.2 — Schedule Product Publishing

**Goal:** Let admins queue draft products to go live at a specific future time. A scheduled cron job flips `is_active=true` hourly.

---

## Database

Migration: `supabase/migrations/00008_product_scheduling.sql`

```sql
-- Schedule column
ALTER TABLE products ADD COLUMN publish_at TIMESTAMPTZ NULL;

-- Partial index: only draft rows with a pending schedule
CREATE INDEX idx_products_publish_at
  ON products (publish_at)
  WHERE publish_at IS NOT NULL AND is_active = FALSE;

-- RPC that advances due drafts to active
CREATE OR REPLACE FUNCTION publish_scheduled_products()
RETURNS INTEGER
LANGUAGE plpgsql
SECURITY DEFINER
AS $$
DECLARE
  updated_count INTEGER;
BEGIN
  UPDATE products
  SET is_active = TRUE,
      publish_at = NULL,
      updated_at = NOW()
  WHERE publish_at IS NOT NULL
    AND publish_at <= NOW()
    AND is_active = FALSE;
  GET DIAGNOSTICS updated_count = ROW_COUNT;
  RETURN updated_count;
END;
$$;
```

Notes:
- The filter `is_active = FALSE` protects against re-running on already-active products (operator could manually activate early).
- Setting `publish_at = NULL` after publishing keeps the index small and avoids duplicate processing.
- `SECURITY DEFINER` allows the Edge Function to invoke it via service role without re-granting row-level permissions.

## Edge Function: `supabase/functions/publish-scheduled/index.ts`

- Cron: `0 * * * *` (every hour on the hour) — registered via Supabase dashboard / config, not in code.
- Authenticates with `Authorization: Bearer <CRON_SECRET>`.
- Calls `supabase.rpc("publish_scheduled_products")`.
- Inserts a `sync_logs` row:

  ```json
  { "function_name": "publish-scheduled", "status": "success", "items_processed": <count>, "completed_at": "<now>" }
  ```

- Returns `{ published: <count> }` on success; `{ error: "<msg>" }` 500 on failure.

## Product edit form: `PublishScheduler.tsx`

- `"use client"` component rendered from `ProductEditForm` only when `product.is_active === false`.
- Props: `{ productId: string, currentPublishAt: string | null }`.
- Controls:
  - `<input type="datetime-local">` bound to local state (displayed in admin's local tz; value is serialised to UTC ISO string before PATCH).
  - **Schedule** button → `PATCH /admin/api/products/<id>` body `{ publish_at: <ISO UTC> }`. Disabled while datetime is empty or in the past.
  - **Publish Now** button → PATCH `{ is_active: true, publish_at: null }`.
  - **Clear schedule** button → PATCH `{ publish_at: null }` (only shown when a schedule exists).
- Uses `fetch` with `cache: "no-store"` then calls `router.refresh()` on success to refresh the server component data.
- Shows a toast (via `sonner`) on each outcome.

Relative-time string for the current schedule is rendered with a tiny helper (e.g. "in 3 hours").

## Dashboard widget: `ScheduledPublishWidget.tsx`

- Server component (no `"use client"`).
- Queries through `getScheduledProducts()` (see next section).
- Renders an admin `<Table>` with columns: Product name (en), Scheduled (relative + absolute), Action (link to edit).
- Empty state: "No products currently scheduled."
- Limit: 10 rows, ordered by `publish_at ASC`.

## Dashboard query (`_lib/queries/dashboard.ts`)

```ts
export async function getScheduledProducts(limit: number = 10) {
  const supabase = await createServerClient();
  const { data, error } = await supabase
    .from("products")
    .select("id, asin, name, publish_at")
    .not("publish_at", "is", null)
    .eq("is_active", false)
    .order("publish_at", { ascending: true })
    .limit(limit);
  if (error) throw error;
  return (data ?? []) as Array<{
    id: string;
    asin: string;
    name: Record<string, string>;
    publish_at: string;
  }>;
}
```
