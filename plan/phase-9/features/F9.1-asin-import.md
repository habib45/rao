# F9.1 — Import Product by ASIN

**Goal:** Give admins a single-field widget on the dashboard to pull an Amazon product into the catalogue by ASIN, producing a draft (`is_active: false`) row that they can then edit.

---

## UX flow

```
Admin dashboard
  └── "Import Product by ASIN" card
       ├── text input: "B0ABCDE123"
       ├── button: "Sync"
       └── state:
            • idle              → empty
            • loading           → spinner + "Fetching from Amazon…"
            • success           → green banner with product name + "Open draft →" link to /admin/products/<id>
            • error             → red banner with server error text
```

- Admin enters exactly 10 alphanumeric characters.
- Client-side validation: pattern `^[A-Z0-9]{10}$` (uppercased before submit). Invalid value disables the button.
- Submit issues `POST /admin/api/products/import` with `{ asin }`.
- On 2xx: show success banner with a link to the new draft.
- On non-2xx: surface the `error` field from the JSON response.
- Uses plain `fetch` (not TanStack Query) — this is a one-shot action with no cache to invalidate.

---

## Edge Function: `supabase/functions/import-product/index.ts`

Responsibilities:

1. Validate `Authorization: Bearer <SUPABASE_SERVICE_ROLE_KEY>` (the admin API route signs the invocation with the service key). This is how Supabase's `functions.invoke` authenticates from the server.
2. Parse `{ asin }` from the JSON body.
3. Construct the PA-API `GetItems` payload with the resources listed in the prompt.
4. Sign it via the existing `signRequest` helper from `_shared/amazon-paapi.ts`.
5. POST to `https://<AMAZON_HOST>/paapi5/getitems`.
6. Extract the first item from `ItemsResult.Items`. If none, return 404 with `{ error: "ASIN not found on Amazon" }`.
7. Return the raw PA-API item so the Next.js route can transform and upsert it. (Keeps transformation logic in Node where it is Vitest-testable via existing `transformPAAPIItem` / `extractPrimaryImage`.)

**Response shape on success:**

```json
{
  "item": { "ASIN": "...", "DetailPageURL": "...", "ItemInfo": { ... }, "Offers": { ... }, "Images": { ... } }
}
```

**Env vars read from `Deno.env`:**
- `AMAZON_ACCESS_KEY`, `AMAZON_SECRET_KEY`, `AMAZON_PARTNER_TAG` (Vault)
- `AMAZON_HOST` (defaults to `webservices.amazon.com`)
- `SUPABASE_SERVICE_ROLE_KEY` (auth gate)

---

## Admin API route: `src/app/admin/api/products/import/route.ts`

- Method: `POST`
- Auth: relies on the admin middleware (already guards `/admin/**`) and service-role Supabase client.
- Zod: `{ asin: z.string().regex(/^[A-Z0-9]{10}$/) }`.
- Behaviour:
  1. Validate body. Return 400 on failure with `{ error: "Validation failed", issues }`.
  2. Invoke `supabase.functions.invoke("import-product", { body: { asin } })`.
  3. If `error` is set or `data.item` missing → 502 `{ error: "Amazon import failed: <message>" }`.
  4. Transform the item with `transformPAAPIItem` (existing helper). Force `is_active: false`.
  5. Upsert onto `products` with `{ onConflict: "asin" }`. Select `id, asin, name`.
  6. If `extractPrimaryImage` returns a URL, upsert into `product_images` with `is_primary: true, sort_order: 0`.
  7. Return 201 `{ product_id, asin, name }`.

---

## Dashboard widget: `AsinImportWidget.tsx`

- `"use client"`
- Uses existing admin UI primitives (`Card`, `Input`, `Button`).
- Exposes three visual states: idle (form), loading (spinner + disabled submit), result (success/error banner with a "Import another" button to reset).
- Success banner links to `/admin/products/${productId}`.
- Uppercases user input on change (ASINs are canonical uppercase).
